# monorepoのレビュー指摘への対応

2026-11-01、developのf0c902dを対象としたレビュー後、ユーザーは書き込みロックの検出とGitのURL置換設定への対応を依頼した。`codex/monorepo-review-fixes`で修正し、既存の方針どおり履歴を残してdevelopへ統合する。

## 変更する振る舞い

### Gitの書き込みロック

従来は`git worktree lock`とmerge等の進行情報を検査していたが、`index.lock`が存在しても削除プレビューを許可し、実削除できた。対象WorktreeのGit管理領域と、リポジトリで共有する管理領域の`.lock`を検出して`GIT_WRITE_LOCKED`を返すようにした。ロックは削除しない。全Worktreeの事前確認、リモートの更新取得後、各Worktreeの削除前に使う検査へ組み込んだ。

共有領域の探索では`worktrees/`を除き、削除対象の専用領域を別に検査する。別タスクの専用indexロックだけで対象の片付けを止めず、そのタスクとロックも保持する。共有するrefs等のロックは停止条件になる。Git外の書き手を排他する仕組みは追加しておらず、片付け前に対象の作業を停止する既存の利用条件は維持する。

### GitのURL置換

従来の`git remote get-url origin`は`insteadOf`適用後のURLを返すため、元の登録URLとの文字列比較が競合を起こしていた。登録の照合には、Git設定から置換前の`remote.origin.url`を取得する。実際の接続先の置換と認証は既存Gitへ任せる。

初回取得・取得途中からの再実行・取得済みリポジトリの確認で同じ照合を使う。登録URLそのものの変更は拒否し、複数URLで取得元が曖昧になる設定も拒否する。新しいURLへの登録変更機能やGit設定の自動書き換えは追加しない。

## 検証

追加した4テストは実装前に全件失敗し、修正後は4件・113 assertionsが成功した。実Gitと一時フォルダを使い、次を確認する。

- 対象のindex・HEAD、共有のpacked-refs・config・ブランチ参照のロックがある間は、プレビューと実行の両方を拒否する。ロック、管理JSON、対象タスクの全Worktreeを保持する。
- ロックを解消すれば片付けでき、別Worktreeの専用ロックと作業場所は保持する。
- 更新取得中に作られたindexロックも、削除前の再検査で検出する。
- HTTPSまたはSSH URLを一時ローカルリポジトリへ置換し、登録済み状態の再利用、同期、作業場所の作成・片付け、同一登録の解除後の再登録が成功する。空の取得元へ初回コミットを作った後の再取得も成功する。
- 実際の登録URLの変更や複数URLの設定は、引き続き拒否する。

一時Git設定だけを使い、利用者のGit設定・認証情報・リモートリポジトリには書き込まない。配布物はソースから生成する。型検査と202ファイルの生成物照合は成功した。全297テスト・2255 assertionsとgit diff --checkも成功した。
