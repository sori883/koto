# 配布する原則の関連付け

この文書は構成整理前の開発・検証記録です。現在の配布構成は[現状資料](current-state.md)を参照してください。

2026-10-20、0.1.6。初期セットアップ後のOKF検証で、同梱する23原則すべてが孤立文書として不合格になる問題を修正した。

## 原因と変更

配布用の `space/babel/principles/` は目次から参照できたが、原則同士の関連リンクがなかった。OKFは目次からの参照をconcept間の関係に数えないため、文書の形式やリンク先が正しくても `validate --strict --drift` は不合格になっていた。

14件の原則に関連リンクを一つずつ追加し、23件すべてに入出いずれかの関連がある状態にした。各リンクには、参照先が元の原則の適用をどう補うかを記した。たとえば、境界で入力を検証する原則から、検証後の型で不正な状態を防ぐ原則へつなぐ。関連を持たせるための新しいまとめ文書や、全件への一括リンクは追加していない。

利用先で追加されていた関係を候補として、配布用本文と照合した。配布先の正本は引き続き `space/babel/` とし、Codex・Claude形式の配布物をbuildで再生成した。CopilotはClaude形式を共用する。原則の適用条件、判断指針、OKFの判定処理、setupの上書き保護は変更していない。

## 検証

`tests/distribution/installed.test.ts` に、リポジトリ外の空のプロジェクトへsetupしてから、配置済みCLIでstrict/drift検証を行う確認を追加した。Codex・Claude Code・Copilotの3ケースは修正前に失敗し、関連リンクの追加後に成功した。

既存知識がある導入先では、独自文書 `knowledge/existing` のみが孤立文書として検出され、strict検証は引き続き不合格になることを確認した。既存文書・指示・履歴の保持、setup再実行、ローカル編集の保護も従来の統合テストで確認する。

mainの基点 `a5bb57f` にある0.1.5の配布物を一時ディレクトリへ取り出し、3製品それぞれで旧版を導入してから新配布物のsetupを適用した。いずれも孤立23件から0件へ変わり、strict/drift検証が成功した。

Bun 1.4.2で全体テスト194件が成功し、Go参照実装を必要とする互換性テスト2件は未実行。型検査、生成物と正本の一致、差分の空白検査も成功した。全体テストの初回には、既存の強制中断テストで監視通知より先に書き手が完了する失敗が1件あった。同じコードの単独実行と全体再実行は成功し、当該テストやセットアップ処理は変更していない。

この変更で確認するのは、配布する原則の参照関係と導入後の検証結果である。エージェントの判断品質や作業速度の改善を測定したものではない。

## 既存導入先

未編集の原則は通常のsetup更新で反映できる。利用先で関連リンクなどを追加済みの場合はローカル編集の保護が働くため、配布側との差を確認して統合する。今回の修正では、お試しプロジェクトの文書・設定・setup管理記録を変更していない。
