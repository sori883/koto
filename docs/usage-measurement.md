# コア利用計測の開発記録

2026-11-15の依頼で、Tasks・Memoryの利用集計、recallの履歴、savepointの保存件数を追加する。setupスキルの計測は対象外とする。同日の確認で、savepointの保存先未指定時は`.space/<project>/savepoint/`を使う方針になった。

## 実装の境界

- `cli/usage/`を独立CLIとして配布する。同日の追加依頼で、stats/listを読み取って説明する補助スキル`koto-usage`を追加する。集計処理の複製や外部依存は追加しない。
- Tasks・MemoryのCLI入口で成否と対象IDを捕捉する。既存のAPIや保存トランザクションは変更しない。
- `.space/<project>/usage/config.json`で明示的に有効化したプロジェクトだけ記録する。計測を有効化しない既存利用者の読み取りは書き込まない。
- CLIがそれぞれ単体で持ち出せるよう、`lib/activity.ts`は3つのCLIに同じ記録器を同梱する。共通runtimeへのimportは作らない。同一プロトコルの保持と各CLI単独での起動をテストする。
- UUIDごとのイベントは一時ファイルからhard linkで公開し、同時実行による追記競合を避ける。recallの同じIDの再送は内容が同じ場合だけ受け付ける。CLIの再実行は別の呼び出しで、Tasksのreplayedを別属性にする。
- ログの保存はCLI本来の処理から独立し、保存失敗をstderrで通知する。異常なログは集計時にエラーにする。一時ファイルは件数を示すが成功イベントには含めない。

## 数字の解釈

CLIの成功はコマンドの結果であり、スキル選択の成功や成果の品質ではない。dry-run、変更なし、一部保存後の失敗は元の応答で判断する。強制停止や記録失敗、未有効の期間は集計から欠落する。

Memoryの詳細usageログは従来通り別に保存する。新旧ログを合算せず、同じ呼び出しの二重計上を避ける。知識の検索結果への出現と本文取得を区別する。記録器は検索語・本文・タスク名を保存しない。

recallはAIの自己申告に基づく1実行1イベントで、手順を実行しなかった呼び出しは検出できない。保存先を確認するためにTasksやMemoryの初期化を要求しない。savepointは現存するMarkdownファイル数を数え、期間別の保存回数として表示しない。既定フォルダ以外と会話のみの保存は対象外とする。

## 検証方針

`tests/usage/activity.test.ts`で実CLIの有効・無効化、Tasksの再試行と失敗、Memoryの取得数と詳細ログとの分離、recallの重複防止、期間・projectの境界、savepoint件数、並行記録、破損検出、symlink、独立実行、JSON入力、raw出力、非ASCII知識IDを検証する。

`tests/distribution/project.test.ts`では移動した利用先の配布CLIで有効化・Memoryの利用・集計まで確認する。既存の読み取り専用・失敗復旧のテストと全配布テストを維持する。過去のsavepointのempirical評価は当時の仕様と証拠なので書き換えず、今回の既定保存先変更とは区別する。

Bun 1.4.2で全335テスト（23ファイル、2,390 assertions）が成功した。TypeScriptの型チェック、配布222ファイルの再生成と一致確認、差分の空白検査も成功した。配布検証で見つかったproject配置先の許可リストへUsage CLIを追加した。setup自体の計測は追加していない。
