# 完了したタスクの資料をアーカイブする

2026-11-04。人がtasks配下のフォルダを見て進行中と完了を区別できるようにする依頼。ユーザーは完了時の自動移動を選択した。

## 配置と責務

task completeで `.space/<project>/tasks/<id>/` を `tasks/archive/<id>/` へ移し、reopenで戻す。台帳、履歴、結果、checkpointを維持する。標準外の成果物、本文、URLは移動・編集しない。資料がないタスクでは空フォルダを作らない。中止・待ち・中断は対象外。

CLIを使わずスキルが移動する案では、CLIだけの利用時に配置が揃わず、途中失敗と参照更新の責任も分かれる。そのためTasks CLIが移動を持ち、スキルは完了条件の判断と本文リンクの確認を持つ。配置だけを示すarchivedを任意属性として追加し、作業状態のcompletedと区別する。

過去に完了したタスクは読み取りやsetupで移動しない。task archiveで明示的に扱う。配置変更だけで依存先の作業を失効させないため、archiveは作業versionを増やさない。同じ理由で他タスクのartifact参照更新もversionを増やさない。履歴のrevisionと操作時刻は残る。新規タスクIDのarchiveを予約し、旧台帳にそのIDがある場合は所有範囲を推測して移動しない。

## 保存と途中失敗

既存のプロジェクトロック内で、移動元・先を検査し、タスク状態・現在の参照・移動予定をstate.jsonへ保存する。続いてフォルダをrenameし、移動予定を解除して再保存する。履歴は一操作分だけ追加する。予定は操作IDと移動元ディレクトリのdevice・inodeを持ち、元か移動先に同じ実体があることを確認する。双方にある、双方にない、別の実体、シンボリックリンクの場合は停止する。

予定が残る間は同じ操作ID・同じ入力による再送だけを受け付け、他の更新とsetupを拒否する。読み取りは可能で、task show・list・statusとdoctorに未完了の移動を表示する。移動後の保存失敗でも再送で二重移動しない。成功済み操作の古い再送は当時の応答のみ返し、現在の配置へ影響させない。

現在のartifact参照は同じproject内の他タスクも更新する。過去のhistory・checkpointは保存時点の参照を保持する。新しい参照の登録時も現在の配置へ合わせる。文書本文のパス、外部リンク、フォルダ外を指す相対リンクは自動修正せず、利用手順で確認を求める。

旧データは追加属性なしで読める。新しい属性を書いた台帳は古いCLIが未知フィールドとして拒否するため、同じ管理ルートでは対応版を揃える。移動と台帳の更新をOS全体で一括コミットするものではなく、予定を残して再開できる方式である。人や別ツールによる同時移動・編集は対象外とし、所有担当を止めてから操作する。

## 検証

実装前のテストでは、自動移動・移動先衝突の検出・途中失敗の再実行・明示的archive等が未実装として失敗することを確認した。実装後は以下が成功した。

- `bun test tests/tasks`：19テスト。完了と再開の往復、再完了、現在の参照と過去の履歴の区別、資料なし、中止、既存完了タスク、依存の保持、プロジェクト分離を確認。
- 同テストで、同名の空フォルダ・シンボリックリンク・旧archiveタスクIDの衝突、rename前後の中断、復元途中の中断、移動元の差し替え、壊れた移動予定の拒否も確認。
- `bun run test`：320テスト、0失敗。Codex・Claude Code・Copilot向け配布物をリポジトリ外へコピーし、そのCLIで資料の自動移動と復元を確認。
- `bun run typecheck`、`bun run build`、`bun run build:check`、`git diff --check`：成功。生成した388ファイルがソースと一致。

この記録はローカルの実装・検証結果であり、mainへのマージ、公開、利用先のインストール更新は未実施。
