# 安全に中断・記録する

「保存して続けて」なら中断せず、保存後に元の作業へ戻る。中断の依頼なら、対象の処理と担当へ停止を伝え、停止結果・途中の書き込み・未コミット変更を確認する。他の作業には触れない。

[Tasks](../tasks/SKILL.md)で同じ仕事のtaskを確認し、最新のversionを取得する。中断できた仕事はtask setでpausedへ、外部条件を待つ仕事はwaitingへ変更する。状態更新だけで実際の処理が停止したと扱わない。

checkpoint saveへ、目的・完了条件・今回の範囲、対象リポジトリとブランチ・HEAD、実施済みと残件、検証の対象版と結果、未コミット変更、停止未確認の処理、次の操作と再開条件をまとめる。既存の成果物とログは参照し、本文を複製しない。CLIの保存先は `.space/<project>/checkpoint/<task>/<id>.json`。管理JSONを直接編集しない。

checkpoint保存はタスクの状態を変更しない。CHECKPOINT_OUTPUT_FAILEDでsavedがtrueなら正本には保存済みなので、原因を解消し同じ操作ID・入力で再送する。過去の同じIDへ別の内容を上書きしない。

コードを変更しない調査などでタスクがない場合は、checkpointのためだけにTasksへ登録しない。再開要約を会話またはユーザー指定のMarkdownに残す。タスク登録自体が依頼されていれば、その対象だけを登録して使う。

Tasksの実行状態・checkpoint・Memory利用ログをソースコードと一緒にコミットすることを必須にしない。ブランチ切り替えで進捗を巻き戻さないよう、利用先の保存方針とGitの追跡状態を確認する。ソース変更のコミット・push・PR・マージは、別途依頼された範囲で行う。

保存結果を読み返し、停止できた範囲、保存したtaskとcheckpoint、未保存・未検証事項、次の操作を報告する。再開では[recall](../recall/SKILL.md)で記録と現在のコードを照合する。中断をタスク完了として報告しない。
