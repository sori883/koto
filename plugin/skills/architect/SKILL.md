# Architect

コードを書く前に、変更が触れるすべてのシステムをたどる。そのうえで、変更の形（型、シグネチャ、モジュールの境界）を異なる二通りで描き、状態のそれぞれに持ち主が一人だけいて、作業のそれぞれにやり方が一つだけあり、呼び出し元が知るべきことが最も少ない方を選ぶ。回避策が繰り返し出てくるなら、継ぎはぎせずに設計し直す。

大きい設計や意見が割れる設計では、一人で描かずに**arena**スキルを使う。
