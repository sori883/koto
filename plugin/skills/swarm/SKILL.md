# Swarm

## 始める

何かを起動する前に、段階ごとに1項目のタスクリスト（`TodoWrite`など、セッションにあるもの）を作る。

1. Frame
2. Fan out
3. Aggregate
4. Report

## 段階A：枠を決める

1. 完了の条件と、swarmが返す成果物または報告を述べる。
2. 形を選ぶ。範囲を分割するか、同じ依頼でN個の担当を競わせるか、両方を組み合わせる。競わせる形や組み合わせる形では、起動の前に`first pass`、`rank all`、`best-of`のどれにするかを宣言する。
3. 担当のモデルは、既定で`model: "opus"`・`effort: "high"`とする。`Agent`ツールが値を拒否したら、既定を使い、そう言う。既定を拒否したら、エラーメッセージにある同じ系列で近い有効な値を使う。モデルを競わせるときは、各担当のモデルを最初に名指しする。各サブエージェントの推論の水準は、**koto-mode**スキルの「サブエージェント」の節に従って、仕事に合わせて選ぶ。
4. 書き込む担当には、それぞれ専用の書き込み先を与える。担当がコミットを確かめる・測るときは、各依頼に正確なSHAを書く。測定の依頼には方法（標本数、1標本が何か、順序）も書く。担当は両方を結果に記録する。

## 段階B：展開する

N個の担当すべてを、一つのメッセージで`subagent_type: "general-purpose"`、`isolation: "remote"`（クラウドで動かす）、`run_in_background: true`、手順3のモデルを指定して起動する。`isolation: "remote"`を外してローカルで動かすのは、担当が利用者のコンピュータ上のものに触れる必要があるときだけとする。

担当が既定以外のpush済みのブランチから始める必要があるときは、依頼にそのブランチを書き、最初にそこへ切り替えさせる。

どの依頼もそれだけで完結させる。目的、範囲、担当する正確な分割または競争の枠、確かめ方、報告する内容を入れる。報告は`PASS`、`ISSUES`、`BLOCKED`のどれかで、証拠を付ける。欠陥を証明できる担当は`ISSUES`を報告し、最初の一つだけでなく、証明できる問題をすべて挙げる。

担当が脱落したら、N-1個で進め、そのことを記録する。

## 段階C：集約する

最終の結果を読む。依頼に書いたSHAと方法を記録していない結果は捨て、その担当を1回だけ起動し直す。2回目も欠けたら、欠落として記録する。欠落は合格に数えない。網羅の場合は、必要な分割すべてに結果がいる。競争の場合は、最初に宣言した選び方を適用する。first pass、rank all、best-ofのどれかを使う。担当の生の出力は貼り付けない。

## 段階D：報告する

会話の中で、まとめた報告を一つ返す。結果の表、問題ごとに1行の説明、欠落や脱落、競争を使った場合はその選び方を入れる。
