# Interrogate

敵対役が変更や設計を壊そうとする。指摘が残るのは、実行で証明されたときだけである。指摘を報告する。修正は適用しない。

## 枠を決める

範囲は利用者が名指ししたものとする。なければ、基準ブランチとのmerge baseから作業ツリーまでの、ブランチの差分とする。利用者のメッセージ、コミット、PRの説明から、**in-your-own-words**スキルで意図を言い直す。意図がはっきりしないときは利用者に聞く。

## 展開する

**arena**スキルの段階Aの手順3と4、段階Bを、4つの変更を加えて実行する。走者の代わりにレビュー担当として、arenaの走者と同じ既定の3席を使う。範囲の未コミットの変更を各worktreeにコピーする。各敵対役は`general-purpose`で起動する。arenaの仕事と根拠の代わりに、各敵対役に範囲、意図、次の依頼文を渡す。

> この変更を壊せ。各指摘は、失敗するテスト、再現スクリプト、誤った動作を示すコマンド出力など、実際のコードに対する実行で証明すること。設計や計画が対象なら、試作を動かすか、現在のツリーを調べる。再現は自分のworktreeに置く。各指摘は、題名、正確なコマンド、それが出力した内容、意図が求める出力を付けて報告する。実行していないものは入れない。スタイル、命名、構成、将来の変更があって初めて問題になるリスクもこれにあたる。指摘なしも正しい結果である。

## 確かめる

各指摘のコマンドを再実行し、arenaの段階Fに従って確かめる。出力が失敗を示し、その失敗が意図を壊すなら、指摘を残す。残りは捨てる。根本原因が同じ指摘はまとめる。

arenaの段階C、D、Eは飛ばす。敵対役はそれぞれ別の失敗を見つけるので、判定は一人の敵対役の一覧ではなく、確かめたすべての指摘を残す。

## 出力

- **意図**：言い直した内容。
- **指摘**：確かめた各指摘について、コマンド、その出力、それが意図をどう壊すか、見つけた敵対役。何も残らなかったら「確かめた指摘なし」と書く。
- **捨てたもの**：敵対役ごとに、捨てた指摘の数とその理由。
