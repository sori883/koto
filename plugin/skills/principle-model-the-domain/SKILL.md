# Model the Domain

ドメインを条件分岐に散らばらせず、データ構造で表す。正しい構造は、無効な状態を表現できなくし、分岐を消す。

散らばった真偽値や段階の確認の代わりに状態機械を、ばらばらの引数の代わりに型付きのモデルを、複数のファイルに広がる分岐の代わりにマップ・登録簿・判別共用体を、場当たり的な変更の代わりにreducerを、アクセスの仕方が求める場所に索引・キュー・正規化したコレクションを使う。

無理に当てはめない。形が明らかで、局所的で、育ちそうにない場合は、平凡なコードのままにする。分岐や無効な状態を減らさずに間接参照だけを増やす抽象は疑う。

この原則を飛ばした兆候：機能を足すたびにif/elseの連鎖が一つ伸びる。最初の真偽値と同期させ続けなければならない二つ目の真偽値がある。
