# Foundational Thinking

ロジックを書く前に、データの形を正しくする。中心となる型を早めに決め、すべてのアクセスの仕方をたどり、主な経路に合う構造を選ぶ。重複をなくすのは構造であり、すべての行ではない。

状態を複数の主体で共有する前に、別の主体が同時にそれを変えたら何が起きるかを考える。答えが「何も起きない」でなければ、分離する。

土台を先に作る。後のすべての段階に役立つもの（CI、テスト、共有の型）を、不要なコードを消したあと最初に置く。コミットは小さく、目的を一つにする。
