### Runtime forensics

**診断に責任を持つ。ソースから推測せず、生きたプロセスに計測を仕込む。** 成果物は根拠を引用した診断であり、修正ではない。

1. 対象に合う操作用のスキル（**control-ui**、**control-cli**）で、該当する面の生きた信号を取る。回り続けるプロセスならCPUプロファイル、リークならヒープスナップショット、表示の乱れならCDPトレースを取る。推測ではなく、実物の成果物にする。
2. 成果物を決定的な証拠まで絞り込む。ホットパス上の関数、リークしたオブジェクトからGCルートまでの保持経路、入力なしに回り続けるループである。大きな成果物はサブエージェントで解析し（原則スキル**guard-the-context-window**）、絞り込んだ結果だけを主のスレッドに残す。各サブエージェントの推論の深さは、「サブエージェント」の節に従って仕事に合わせて選ぶ。
3. 信じる前に仕組みを証明する。実行中のプロセスにCDPのevalで計測を差し込むか、再読み込みせずに生きたコードへホットフィックスを当て、仮説を安く確かめる。
4. 結果をソースに対応づける。ファイル、シンボル、メモリを確保する行やスケジュールする行である。
5. スループットの確認は1行で済ませる：`throughput checkpoint: n/a, read-only forensics`。

**返答：** 取った信号、絞り込んだ結果、仕組みをどう証明したか、ソースの位置、成果物のパス。頼まれない限り修正はしない。原因が分かったら、Bug fixかPerfへ戻す。
