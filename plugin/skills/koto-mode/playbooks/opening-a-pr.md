### Opening a PR

ほかのすべてのプレイブックの最後に呼び出される。

trunkから作ったgit worktreeで作業し、関係のない作業を入れない。小さく着地できるコミットにrebaseで整える。コミットの前に、差分に対して**deslop**を実行する。

PRを開いたら、作業のチケットがあれば、Skillツールで`koto:ticket`を呼び、その「終える」の手順でチケットを閉じる。PRのURLを成果物に、何をしてどう確かめたかを結果に書いて`done`にし、その更新を同じブランチにコミットしてpushする。チケットはPRを開いた時点で完了とし、それ以降のレビュー対応やマージではチケットに触れない。

タイトル：`type(scope): subject`。変更を担う実在のシンボルがあれば、その名前を入れる。本文：1分で読める40行未満の説明とし、次の`##`見出しをこの順で使い、中身のない見出しは省く。`## 目的`、`## 変更内容`、`## 範囲`、`## トレードオフ`（レビューする人が聞きそうな、採らなかった代替案だけ）、`## 影響範囲`、`## 検証`。

後続の作業はベースブランチで積み重ねる。PRはready（下書きではない状態）で開き、実行環境のPR用ツールがあれば`draft: false`で使う。なければ`--draft`を付けずに`gh pr create`を使う。OriginのCLIがリポジトリを解決できるときは`origin pr create --status open`を使う。PRを開いても見守りは始まらない。
