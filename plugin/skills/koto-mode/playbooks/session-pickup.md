### Session pickup

**再開地点は自分が持つ。前の作業の記録を読み、やり直さない。**

1. 前の作業の記録を見つける。現在の作業フォルダのClaude Codeの会話記録（`~/.claude/projects/<作業フォルダのパスを変換した名前>/<セッションID>.jsonl`。サブエージェントの記録はその`<セッションID>/subagents/`の下。`~/.claude/projects/*/`をまたいでglobしない。作業フォルダの境界を越え、無関係なプロジェクトの非公開の会話を読むことになる）、クラウドのセッションのURL、またはpushされたブランチのいずれかである。まずメタデータの概要と最後のメッセージを読み、それから遡って判断の分かれ目を探す。長い会話記録はサブエージェントで解析し、主のスレッドには縮約した時系列だけを残す（**principle-guard-the-context-window**スキル）。各サブエージェントの推論の深さは、「サブエージェント」の節に従って仕事に合わせて選ぶ。
2. 作業の状態を復元する。ブランチと作業ツリー、すでに取り込まれたもの（`git log`、基点に対する`git diff`）、未完了のタスク、下された判断。前の作業の記録は信頼できる入力である。それを導き直したくなる偏りに抗う。
3. 完了分と残りの差を取る。出荷されたものと計画されたものを比べ、再開地点を名指しし、前の再現手順を再実行したり完了済みの作業をやり直したりしない。「一から確かめよう」とするのは、信頼できる記録を信用できないものとして扱っていることになる。
4. 残りの作業を該当するプレイブックへ回し、結論の種類を選ぶ。実行を続ける、仕上がった提案を出す、前の結論を追認または覆す、失敗した実行を振り返る、のいずれかである。再開のプレイブックはここで終わる。残りは回した先のプレイブックが受け持つ。
5. 引き継いだ主張を、元の目的に照らして実物で検証する（**principle-prove-it-works**スキル）。前の作業の自己報告が合格でも、それは証明にならない。

**返答：** 前のエージェントが止まった場所、引き継いだものとやり直したもの（やり直しはないのが理想）、再開地点、結果。
