# Test Behavior, Not Implementation

テストは、コードの利用者がインターフェースを通して観察できることについての主張である。戻り値、エラー、読み返せる状態、外部のシステムへの影響がそれにあたる。非公開の補助関数、内部の呼び出し順、途中のデータは実装である。

各テストを、想像した2つの編集で判定する。

- **振る舞いを壊す**（値を間違える、効果を飛ばす・二重にする）。それでもテストが通るなら、何も証明していない。よくある原因は、緩い確認、テスト対象のコードで計算した期待値、テスト自身が作ったデータへの確認である。
- **内部を変え**、観察できる結果はすべて保つ。それでテストが失敗するなら、実装に縛られている。

1つ目の編集を捕まえ、2つ目の編集を通るテストを残し、それ以外は書き直すか消す。具体的な入力で公開インターフェースからコードを動かし、期待値は要件から導く。外部のサービスが受け取るものは振る舞いであり、内部の補助関数の呼び出しは振る舞いではない。「これは起きない」には、それが実際に起きる場合を組み合わせる。確認するのは、呼び出し側が分岐に使うエラーの種類であり、メッセージではない。
