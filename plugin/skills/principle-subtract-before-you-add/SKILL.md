# Subtract Before You Add

システムを変えるときは、先に複雑さを取り除き、それから作る。既定は引き算とする。

単純化を継続的な投資にする。同じかより小さい表面のまま、見つけたときより少し単純で、少し多くのことができる設計を残す。

- 作る前に消す。
- 磨く前に削る（品質に投資する前に、最小の形にする）。
- 想像した例外ではなく、観察した使われ方に合わせて設計する。
- 仕様が求める以上の、推測にもとづく検証・解析・ガードを書かない。
- プロンプトを単純にする（重複した指示、過剰なひな形を消す）。
- 新しい内容のない参照は、中身のない入口として残さず消す。
