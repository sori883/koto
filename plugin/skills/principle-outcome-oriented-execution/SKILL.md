# Outcome-Oriented Execution

途中の状態を滑らかに保つことより、意図した、確かめられる最終状態を優先する。

**理由：** 途中のすべての段階を完全に安定させようとすると、一時的な互換用コードが生まれ、長く残る負債になりやすい。目標の構成に収束させ、明示した確認の区切りで正しさを示す。

**中心の決まり：**

- 移行中の安定より、最終状態の完全さを優先する。
- 途中で壊れることは、計画され、範囲が決まり、元に戻せるなら許容する。

**歯止め：**

- 区切りが明確な計画的な書き直し・移行にだけ使う。
- 一時的に壊れてよい場所を宣言する。
- 移行中も、手を入れている部分には信頼できる確認を残す。
- 計画の完了時には、静的な確認と実行時の確認をすべて行う。
