# Build the Lever

作業が自明でなければ、手でやらずに、それをする道具（コード変換、スクリプト、生成器、再実行できる確認）を作る。基準は繰り返しの多さではなく、自明かどうかである。道具を省いてよいのは、明らかな編集が2、3か所だけの場合である。

- 最初の一単位は手で行い、それから道具を作り、その単位で再実行して道具を確かめる。何度実行しても安全にする。
- 決まった結果を出す道具は、並行作業に勝る。並行作業にするときは、手順、確認の約束、守る範囲を、任せる相手が読めて編集できない一つのスキルとして書く。
- この原則を適用すると、ファイルができる。差分にスクリプト、コード変換、生成器、任せる相手用のスキルがなければ、適用していない。作業がセッションより長く残るなら、それをコミットする。
- 仕事をする、または正しさを示す最小のスクリプトを作る。枠組みは作らない。
