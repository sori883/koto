# Separate Before Serializing Shared State

並行して動く主体が同じファイル、ブランチ、キー、オブジェクトに書くかもしれないときは、まず、本当に一つの共有オブジェクトが必要なのか、それぞれ独立した事実を書き出しているだけなのかを問う。既定では、主体ごとに自分のファイル、キー、ブランチ、状態ディレクトリを持たせ、読む場所でだけまとめる。2人の作業者が一つの`state.json`にそれぞれのフィールドを書くのも、共有された変更である。

一つの共有された書き込み先が本当に不変条件である場合だけ、アクセスを構造的に直列化する（ロックファイル、書き込み担当を一人にする、段階を順番にする、比較して交換する）。指示文は並行制御にならない。「ロックが必要だ」は、まず疑うべき兆候である。
