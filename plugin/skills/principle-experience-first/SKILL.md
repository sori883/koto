# Experience First

実装の都合と使う人の喜びがぶつかったら、喜びを選ぶ。

- すべての機能、操作、選択肢に、存在する理由を求める。
- 少なく、よく出す（3つの機能で磨かれた体験は、10の機能で粗い体験に勝る）。
- 決める前に試作する（設計の判断は、本番のコードより使い捨てのHTMLで行う方が安い）。
- 細部を正しくする（遷移、揃え、余白、反応、エラー時の状態）。
- 中心の流れを引き締める（すべての機能は中心の作業に役立つか、邪魔にならない場所にいる）。

使う人とは、その成果を受け取る人である。画面なら最終的な利用者、ライブラリや内部APIなら、それを読み込む同僚である。次にそのコードを保守する開発者も使う人である。その人たちの体験も同じように重んじ、影響はその人の立場から説明する。

土台は体験に仕えるものである。foundational-thinkingは作業の「順序」を決め、この原則は「目標」を決める。
